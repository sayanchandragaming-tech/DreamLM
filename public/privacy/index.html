Data and storage

DreamLM privacy

This page describes data flows visible in the current DreamLM website code and user-facing notices.

Sign-in and account information

Email and password sign-in and Google sign-in are handled through Supabase Authentication. The client keeps an authenticated session. When a session is established, the application checks beta-user status through Supabase and uses session details such as email or a profile name to label the workspace.

When Google sign-in is selected, the authentication flow also involves Google. Dream Circuit does not control the separate services’ own data practices.

Conversations

The browser stores conversation messages, titles, and timestamps in local storage so they can appear in chat history. When you submit a message, the website sends its text and a conversation session identifier to the configured DreamLM response service and displays the returned response.

The application notice says conversations may be reviewed by Dream Circuit for beta testing, debugging, safety, and model improvement. The website code does not specify how long the response service or connected services retain submitted data.

Browser preferences

The selected appearance theme is stored in local storage. Deleting a conversation in the workspace removes it from the browser’s locally stored conversation history; this interface action does not state or guarantee deletion from connected services.

Other services

The website loads typefaces and Material Symbols from Google Fonts. Supabase provides the authentication and beta-account functions used by the app. Chat requests are sent to the DreamLM response service configured for the website. These services receive requests needed for their stated function.

Limits of this description

The repository does not specify service-side retention periods or provide a dedicated privacy request process. This page is limited to behavior that can be verified in the current website and its displayed notices.
